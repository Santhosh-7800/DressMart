# DressMart Project Cleanup Report

Generated as part of a project-wide audit. Scope: remove confirmed-unused/duplicate/scratch/generated
files only. No source code, product images, Firebase/Android/Capacitor configuration, or routes were
touched. The repository currently has a very large amount of legitimate, uncommitted feature work
(visible in `git status`) from prior development phases — none of that was treated as cleanup material.

## METHODOLOGY

For every candidate file, its exact filename was grepped across the entire repository (`.ts`, `.tsx`,
`.js`, `.mjs`, `.json`, `.md`, `.xml`, `.gradle`, config files) to confirm zero references before
classifying it as safe to delete. `git ls-files` was used to check tracked/untracked status.
`package.json` scripts, `capacitor.config.ts`, and `scripts/generateCapacitorAssets.mjs` were read in
full to confirm what each build/asset pipeline actually consumes.

## KEEP (verified required — not touched)

- All `frontend/src/`, `backend/functions/src/`, `mobile/` application source code, including every file
  currently showing as modified (`M`) or untracked (`??`) in `git status` — this is in-progress,
  intentional feature work from recent development phases (support tickets, delivery management,
  business reports, splash screen rework, seller tooling, etc.), not cleanup material.
- `documentation/README.md`, `documentation/ARCHITECTURE.md` — project docs.
- `scripts/*` — every script is referenced by a `package.json` script (`predev`, `prebuild`, `seed*`,
  `validate:*`, `images:scan`, `emulators`, `cap:sync`) or imported by another script (`lib/`).
- `config/tsconfig.scripts.json` — referenced directly by the root `typecheck` script.
- `mobile/android/app/src/debug/AndroidManifest.xml` — standard Capacitor/Android Studio debug
  source-set manifest (enables cleartext traffic for local dev builds). Required for debug builds.
- `frontend/src/assets/splash-source/dressmart-splash-original.png` and
  `frontend/public/images/splash/dressmart-splash-hero.webp` — new splash-screen feature assets, used
  by the new (untracked) `SplashScreen.tsx` component.
- `mobile/assets/icon.png`, `icon-foreground.png`, `icon-background.png` — actively regenerated/consumed
  Capacitor icon sources.
- `.env`, `.env.example`, `.env.production.local` — required local/deploy configuration. Contents were
  not printed or altered.
- `package.json`, `package-lock.json`, `render.yaml`, `vercel.json` — deployment/build configuration.
- `node_modules/` (root, `frontend/`, `backend/functions/`) — gitignored, regenerable via `npm install`,
  left untouched (deleting it would require a reinstall for no benefit — it's already correctly excluded
  from version control).
- `.emulator-data/` — the live `--export-on-exit` target for the local Firestore/Auth emulator
  (`package.json`'s `emulators` script and `scripts/ensureEmulatorRunning.ts` both point here). Only 5KB.
  Left untouched.
- `.vscode/settings.json` — local editor config.

## POSSIBLE UNUSED (requires manual confirmation — not deleted)

None found with the confidence bar required for deletion. A search for classic duplicate/backup naming
patterns (`*-old.*`, `*-copy.*`, `*-final*.*`, `*-backup.*`, `*.bak`, `*.orig`) across
`frontend/src`, `backend/functions/src`, and `mobile` returned zero matches — no stale duplicate
components, pages, or hooks were found by name. A full unused-file/dead-code sweep of `frontend/src`
was intentionally **not** performed automatically in this pass: the repository currently contains
dozens of very recently added, still-integrating files (support tickets, delivery management, business
reports, etc.) that would appear "unreferenced" to a naive heuristic while actually being live
in-progress work — flagging them risks exactly the kind of accidental feature deletion this audit was
asked to avoid. If a deeper dead-code sweep is wanted, it should be run as its own explicitly-scoped
follow-up so each finding can be checked against dynamic imports/lazy routes individually.
